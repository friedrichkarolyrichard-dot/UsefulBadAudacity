AUTO DOKTOR SCHWEIZ – REPLIT MVP V1

ROLE

You are an expert full-stack developer, UX/UI designer and AI product engineer.

Build a real, working MVP web application for a new Swiss automotive service.

The project name is:

AUTO DOKTOR

Slogan:

„Ihr Auto. Unser Problem.“

Alternative slogan:

„Sie fahren. Wir kümmern uns um den Rest.“

Initial service area:

Thun, Gwatt, Steffisburg, Spiez and Berner Oberland, Switzerland.

The application must be professional enough to show to real customers.

This is NOT just a visual mockup.

Build a functional MVP.

⸻

1. BUSINESS CONCEPT

AUTO DOKTOR combines:

* automotive expertise
* AI-assisted preliminary vehicle problem analysis
* professional mechanic review
* vehicle pickup and delivery
* vehicle checks
* MFK preparation
* repair coordination

The key customer promise is:

„Sie geben uns das Problem. Wir kümmern uns um den Rest.“

The first MVP should focus on one simple customer journey:

Customer has a car problem → reports it online → AI creates a preliminary assessment → customer can request a professional diagnosis → AutoDoktor contacts the customer.

Do NOT build a huge platform yet.

⸻

2. PRIMARY MVP OBJECTIVE

The first goal is to acquire the first 10 paying customers.

Therefore the MVP must prioritize:

1. Professional landing page
2. Problem reporting form
3. Vehicle information
4. Photo upload
5. Optional video upload
6. Fault-code input
7. AI preliminary assessment
8. Customer contact details
9. Admin dashboard
10. Case management
11. Diagnosis booking request
12. Pickup request

Everything else should be Phase 2.

⸻

3. TECHNOLOGY

Use a modern, simple and maintainable stack.

Preferred:

* React
* TypeScript
* Next.js if supported well by the environment
* Tailwind CSS

Do not introduce unnecessary microservices.

Do not build unnecessary infrastructure.

4. IMPORTANT COST REQUIREMENT

This is a low-budget startup.

The system must be designed to run cheaply.

Use free or low-cost services wherever practical.

Do not add paid services unless necessary.

NEVER hardcode API keys.

9. AI ANALYSIS

After submitting the problem, send the structured information to the AI.

Create an AI service module.

The AI should return structured JSON.

Example structure:

{
  "urgency": "medium",
  "possible_causes": [],
  "recommended_diagnostic_steps": [],
  "customer_explanation": "",
  "mechanic_summary": "",
  "confidence": "low"
}

The AI must NOT provide a guaranteed diagnosis.

Use language such as:

„Mögliche Ursache“

„Wahrscheinliche Ursache“

„Weitere Diagnose erforderlich“

Never claim certainty when there is insufficient information.

35. DEVELOPMENT RULE

Before writing a large amount of code:

1. Analyze the requirements.
2. Propose the architecture.
3. Create the project structure.
4. Implement the MVP incrementally.
5. Test every major feature.
6. Fix errors.
7. Make the application mobile responsive.
8. Prepare deployment instructions.

Do not create fake integrations.

If something requires an external API key, create a real integration using environment variables if possible.
